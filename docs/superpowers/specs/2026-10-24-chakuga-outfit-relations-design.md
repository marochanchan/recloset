# 着画とコーデ関係DB 設計書

- 作成日: 2026-10-24
- 対象: Re:Closet（`/Users/marochan/gs-works/recloset`）
- 状態: ユーザー確認待ち → Codex（Astra）レビュー → 開発プラン

## 1. 目的

これまでの Re:Closet は、床や机に置いた服の写真（平置き）で服を管理するアプリだった。今回は、鏡の前で撮った**着画**（写真と数秒の動画）とスマホの外出写真を取り込み、**服と服の関係DB**と**コーデ履歴**を作る。

- 今回の中心は、画面よりも**データの構造**。「いつ、どの服を一緒に着たか」を貯め、よく着る組み合わせ、1着から別の服をたどる、季節の比較など、いろいろな角度から使えるようにする。
- コンセプト：**ごちゃごちゃのクローゼットを全部登録すると、つながりのマップで遊べるようになる。だから撮影のやる気が上がる。**
- 優先順位：かっこいい・使いたい・手間が少ない（UX）が先。AIの費用と事業モデルは二の次。

### 成功の基準

1. 鏡の前（開発機の Mac ＋ Web カメラ）で撮影すると、AI が写っている服を見分けて手持ちの服の候補を出す。合っていれば「確定」1回でコーデとして記録できる。
2. スマホの外出写真・動画を取り込むと、撮影日のコーデとして記録できる。
3. 服の詳細ページの「つながりのマップ」で、一緒に着た服をたどり、期間を動かして変化を見られる。
4. AI の候補と最終的な選択が記録され、1位の候補の正解率を測れる。
5. 2026-11-10 までに、GGA のデモに必要な機能が本番環境で動く（12章）。

## 5. 用語

| 用語 | 意味 |
|---|---|
| 着画 | 服を着た姿の写真・動画。鏡の前で撮るものと、スマホの外出写真がある |
| コーデ | 1回分の組み合わせ（`outfits`）。写真がなくても作れる |
| 確認待ち／確定 | コーデの状態。確定したコーデだけを集計に入れる |
| 自動の関係 | コーデ履歴から計算する関係（一緒に着た回数、最後に一緒に着た日、よく着る組み合わせ） |
| 自分で付ける関係 | セットアップ、色違い・同じ型。グループとして持つ |
| 入れ替え候補 | 同じカテゴリーで、合わせる相手がかぶる服 |
| 出番待ちの服 | 登録済みで、まだどの服ともつながっていない服 |
| 最近 | 直近3か月 |
| 季節 | 春3〜5月、夏6〜8月、秋9〜11月、冬12〜2月 |

## 6. データベース

### 6.1 テーブル

新しいテーブルはすべて `user_id`、UUID の主キー（関連表を除く）、`created_at`、`updated_at` を持つ。日付の区切りは**日本時間**で統一する。

**`outfits`**（コーデ1回分）

| 列 | 内容 |
|---|---|
| `worn_on` | 着た日（date、日本時間） |
| `source` | `mirror`（鏡で撮影）／`upload`（アップロード）／`manual`（写真なし）／`wear_suggestion`（「今日着た」からの提案） |
| `status` | `pending`（確認待ち）／`confirmed`（確定） |
| `analysis_status` | `none`／`queued`／`running`／`done`／`failed` |
| `analyzed_media_id` | AI が解析した代表の写真 |
| `note` | メモ |
| `client_request_id` | 送り直しで二重登録しないための依頼ID。`(user_id, client_request_id)` で一意 |
| `confirmed_at` | 確定した日時 |

**`outfit_media`**（着画の写真・動画）

| 列 | 内容 |
|---|---|
| `outfit_id` | どのコーデか |
| `kind` | `photo`／`video` |
| `provider` | `cf_images`／`cf_stream`。将来、別の保存先に移せるようにする |
| `provider_asset_id` | Cloudflare 側の ID（Images の画像 ID、Stream の動画 UID） |
| `status` | `uploading`／`ready`／`failed` |
| `width`、`height`、`duration_sec` | 大きさと長さ |
| `taken_at` | 撮影日時（EXIF、読めなければ null） |
| `sort_order` | 並び順 |

**`outfit_items`**（コーデに入っている服）← 関係DBの中心

| 列 | 内容 |
|---|---|
| `outfit_id`、`item_id` | 主キーはこの2つ |
| `wear_log_id` | ひも付く着用記録 |
| `source` | `detected`（AI の認識から）／`manual`（手で追加） |
| `detection_id` | もとになった AI の認識結果（あれば） |

**`outfit_detections`**（AI が見つけたもの1つ1つ）← 知見の記録

| 列 | 内容 |
|---|---|
| `outfit_id`、`media_id` | どのコーデの、どの写真か |
| `person_index` | 写っている人の番号。外出写真で複数人いる場合に使う |
| `bbox` | 写真の中の位置。0〜1 に正規化した x, y, w, h |
| `category`、`subcategory`、`color`、`pattern` | AI が出した属性 |
| `detector_model`、`compare_model` | 使ったモデル |
| `candidates` | jsonb。`[{item_id, score, reasons[], stage: "rule" or "compare", rank}]` |
| `decision` | `matched`（照合した）／`registered`（新しく登録した）／`ignored`（無視した）／null |
| `chosen_item_id`、`chosen_rank`、`decided_at` | 自分が選んだ服、それが何位の候補だったか、選んだ日時 |

**`item_groups`** と **`item_group_members`**（自分で付ける関係）

- `item_groups.kind`：`setup`（セットアップ）／`same_model`（色違い・同じ型）。種類はあとから増やせる。
- `item_group_members` は `(group_id, item_id, kind)` を持つ。`(user_id, item_id, kind)` で一意にして、1着が入れるのは種類ごとに1グループまでにする。`kind` は `(group_id, kind)` の複合外部キーでグループと一致させる。

**月ごとのサマリー**（2層目）

| テーブル | 1行の単位 | 列 |
|---|---|---|
| `item_monthly_stats` | 服1着 × 1か月 | `wear_log_count`（着用記録の件数）、`worn_days`（着た日数。同じ日の重複は1日）、`outfit_count`（確定コーデに入った回数）、`last_worn_on` |
| `item_pair_monthly_stats` | 服2着（`item_a < item_b`）× 1か月 | `outfit_count`、`together_days`、`last_worn_on` |
| `outfit_combo_monthly_stats` | 服の組み合わせ一式 × 1か月 | `combo_key`（並べ替えた服 ID のハッシュ）、`item_ids`（uuid[]）、`outfit_count`、`last_worn_on` |

- 一意キー：`(user_id, item_id, month)`、`(user_id, item_a, item_b, month)`、`(user_id, combo_key, month)`。
- `month` は月の1日の date（日本時間）。

**`media_deletion_queue`**（Cloudflare の削除待ち）

- `provider`、`provider_asset_id`、`attempts`、`last_error`。DB から消したのに Cloudflare 側の削除に失敗した写真・動画を残しておき、あとでもう一度削除する。

**既存テーブルの変更**

- `clothing_items` に `archived_at` を足す。一覧ではしまった服を出さないが、過去のコーデと集計には残る。
- カテゴリーに「小物」（`accessory`）を足す。カテゴリーはアプリ側で管理しているので、テーブルの変更は要らない。種類は、スカーフ・ストール、帽子、ベルト、その他。

### 6.2 書き込みはすべて RPC を通す

サマリーがずれないように、サマリーに関係する書き込みはすべて RPC（DB の関数）を通す。プロジェクトの方針に合わせて、DB トリガーは使わない。

| RPC | 内容 |
|---|---|
| `create_outfit_draft` | 確認待ちのコーデとメディアの行を作る。同じ `client_request_id` なら前回と同じ結果を返す |
| `confirm_outfit` | 服の一覧・日付・メモを受け取って確定する。確定済みのコーデを直すときもこの RPC を使う |
| `delete_outfit` | コーデを消す。着用記録は残し、メディアは削除待ちに入れる |
| `record_wear_today` | 今の「今日着た」を置き換える |
| `archive_item`／`unarchive_item` | 服をしまう／戻す |
| `hard_delete_item` | 服を完全に削除する。過去の記録からも消える |
| `set_item_group` | 自分で付ける関係を作る、変える |
| `rebuild_monthly_stats(user, month)` | その月のサマリーを、その月の事実から作り直す（内部用） |
| `rebuild_all_stats(user)` | 全期間を作り直す（万一のため） |

**すべての RPC で守ること**

- 最初にユーザーごとのロック（`pg_advisory_xact_lock`）をかけ、同じユーザーの更新を1つずつ順番に処理する。
- 参照するデータすべて（服、着用記録、メディア、コーデ）が本人のものか、互いに対応しているかを確かめる。外部キーで保証できる部分は外部キーでも縛る。
- サマリーは「1を足す・1を引く」ではなく、**変更があった月だけを作り直す**。日付を別の月に直したときは、元の月と新しい月の両方を作り直す。
- 書き込みとサマリーの作り直しは、1つのトランザクションで行う。

**`confirm_outfit` の着用記録**

- 服ごとに `wear_logs` を作り、`outfit_items.wear_log_id` にひも付ける。同じ日に、まだどのコーデにもつながっていない「今日着た」の記録があれば、新しく作らずにそれを使う。
- 過去の日付の着用記録の `worn_at` は、その日の 12:00（日本時間）にする。今日なら今の時刻にする。
- `wear_count` は着用記録の件数と一致させる。`last_worn_at` は今の値と比べて新しいほうを残し、過去の日付で確定しても古い日付に戻らないようにする。

**削除の扱い**

- 写真や動画を消しても、組み合わせの記録は残る。
- コーデを消しても、着用記録は残る。
- 服を完全に削除すると、その服を含むコーデの行も消え、関係する月のサマリーを作り直す。

### 6.3 アクセス権限（RLS）

- 今までと同じく、本人だけが読み書きできる。
- サマリーとキューは、本人が読めるだけにする。書き込みは RPC からだけにする。
- 公開（サブプロジェクト2）は、あとで別の RPC として足す。

### 6.4 読み出し

- Looks の着画の一覧とカレンダーは、表示している月の詳細の履歴（`outfits`、`outfit_items`）を読む。古い月も、詳細の履歴は消さないのでそのまま読める。
- 「よく着る組み合わせ（最近3か月）」も、詳細の履歴から数える。
- **季節や年の比較**は、月ごとのサマリーを足して作る。
- 服の詳細ページのマップは、選んだ期間の `item_pair_monthly_stats` を足して作る。「入れ替え」と「広がり」も同じデータから計算する。
- 計算の部分は、データを渡すと結果が返るだけの関数（純粋な関数）として `lib/` に置き、DB を使わずにテストする。

## 7. 取り込みと AI の流れ

### 7.1 記録の入口

- どの画面でも、右下に「＋記録」ボタンを出す。押すと次の4つから選べる。前回使った方法には「前回」の印を付ける。
  1. その場で撮影する
  2. 写真・動画から取り込む
  3. 写真なしで記録する
  4. 「今日着た」から提案する
- Today の一番上に「今日のコーデを記録」カードを出す。まだ記録していない日だけ表示し、記録したらその日の着画に変わる。

### 7.2 撮影（Mac ＋ Web カメラ）

- カメラを選べるようにする（Mac 内蔵のカメラと外付けの Web カメラ）。
- 映像は**鏡と同じ左右反転**で映す。保存する写真は反転を戻し、ロゴなどが正しい向きになるようにする。
- 「撮影」を押すと、5秒のカウントダウン（画面表示と音）のあと写真を撮り、続けて約5秒の動画を録画する。撮ったものを見て「保存」か「撮り直し」を選ぶ。
- 録画の形式は、ブラウザが対応していれば MP4（H.264）、対応していなければ WebM にする。どちらも Stream が変換する。
- 「撮影を始める合図」は差し替えられる部品にする（今はボタン、将来は音声やリモコン）。
- 「撮影待機」の全画面モード：カメラを常に表示し、ボタンは1つだけにする。
- カメラが使えない、または録画できないブラウザでは、写真だけ撮るか、アップロードに切り替える。

### 7.3 アップロード（スマホの外出写真など）

- 写真と動画をまとめて選べる。1つのコーデに複数の写真・動画を付けられる。
- 写真は、送る前にブラウザで撮影日（EXIF）を読み取り、コーデの日付の初期値にする。読めないときは手で入力する。
- 写真は、今の `lib/image-processing.ts` のアップロード用の設定で縮小し、JPEG にし直してから送る。位置情報などのメタデータは消える。
- 動画の長さの上限は60秒にする。

### 7.4 保存（Cloudflare）

1. `create_outfit_draft` で、確認待ちのコーデとメディアの行（`uploading`）を作る。
2. サーバーが本人のコーデか確かめてから、Cloudflare の**一度だけ使えるアップロード URL**（Images と Stream の Direct Creator Upload）を発行する。Cloudflare 側の記録（メタデータ）にもユーザー ID とメディア ID を入れる。
3. ブラウザから Cloudflare へ直接送る。サーバー（Vercel）を大きなファイルが通らないようにする。
4. 写真は、送り終わったら `ready` にする。動画は、Stream の変換が終わった通知（webhook）を受けて `ready` にする。通知は署名を確かめる。開発機のように通知が届かない環境のために、画面を開いたときに Stream の API で状態を確かめる処理も用意する。
5. すべて送り終わったら、AI の解析を始める。

### 7.5 AI の解析（裏で進める）

- Next.js の `after()` で、レスポンスを返したあとに解析を進める。画面を閉じても解析は進む。`maxDuration` で時間の上限を決める。
- 状態は `outfits.analysis_status` に持たせる。失敗したら「もう一度解析」か「手で選ぶ」を選べる。
- 解析するのは**代表の写真1枚**だけにする。最初の写真を代表にし、あとから変えられる。足りなければ「この写真も解析」で追加する。

**3つの段階**

1. **見分ける（AI）**：写真から服・バッグ・小物を見つけ、カテゴリー・種類・色・柄と写真の中の位置を返す。人が複数写っていれば、人ごとに分ける。モデルは既存と同じ系統で始め、精度が足りなければ上位のモデルに上げる（費用は二の次）。
2. **候補を順位付け（ルール）**：見つけたもの1つずつに、手持ちの服から候補を最大5着出す。次の点数を足し、理由も付ける（例：「色と種類が一致」「このデニムとよく合わせている」）。
   - カテゴリー・種類・色・柄の一致
   - 色違い・同じ型のグループ
   - セットアップの相方が写っている
   - 他に写っている服と一緒に着た回数
   - しまった服は候補から外す
3. **見比べる（AI）**：上位2つの点数差が小さいとき（初期値は、1位の点数の15%未満。定数にして、記録を見て調整する）は、写真の該当部分と候補の服の写真を AI に見比べさせて、順位を調整する。

- 「見分ける」と「見比べる」は差し替えられる部品（インターフェース）にする。今は Gemini、将来はローカルの AI に替えられる。テストではダミーを使う。
- 段階2と段階3の順位と、最終的に自分が選んだ結果は、両方とも `outfit_detections` に記録する。

### 7.6 新しい服として登録

- 確認画面で「新しく登録」を選ぶと、サーバーが写真の中の位置をもとに服の部分を切り出し、今までどおり Supabase の服の写真（`clothing_images`）として保存する。
- 種類や色は AI の結果を初期値にして、それを見て確定してもらう。

## 8. 写真・動画の保存（Cloudflare）

- **写真**：Cloudflare Images。署名付き URL でしか見られないようにする（`requireSignedURLs`）。大きさの種類（バリアント）は3つ。
  - `thumb`：一覧用、長辺480px
  - `display`：詳細用、長辺1600px
  - `analysis`：AI 解析と切り出し用、長辺2048px
- **動画**：Cloudflare Stream。署名付きトークンでしか再生できないようにする。回線に合わせて画質を変えて配信する。一覧ではサムネイルを出し、画面に入ったら音なしで動くプレビューを再生する。
- **署名**：URL とトークンは、サーバーが短い期限（1時間）で作る。鍵は環境変数に置く。
- **既存の服の写真**：Supabase Storage のまま。Supabase は DB とログインにも使い続ける。
- **差し替えやすさ**：Cloudflare とのやりとりは1つの部品（MediaStore）にまとめる。テストではダミーを使う。
- **費用**：最初は Images と Stream で月 $10 ほど（それぞれ $5 単位の枠を買う）。
- **プレゼンでの説明**：「着画のメディアは Cloudflare の画像配信と動画配信で、世界中どこでも速く表示する」。

## 9. 画面

### 9.1 メニューと記録

- メニューは Today／Closet／Looks／Loop／My Page の5つのまま。どの画面でも右下に「＋記録」ボタンを浮かべる（一覧の端と少し重なる）。
- 確認待ちのコーデは、Looks のバッジで知らせる。

### 9.2 確認画面

- **見た目**：着画を大きく見せ、写真の上に枠と、確定した服の名前を重ねる。
- **操作**：候補の一覧も常に表示し、上位の候補を最初から選んだ状態にする。当たっていれば「確定」1回で終わる。
- **2つをつなぐ**：写真の枠をタップすると一覧のその行が光り、行を選ぶと写真の枠が光る。
- **配置**：PC では左に写真、右に一覧。スマホでは上に写真、下に一覧。
- 「＋アイテムを追加」で、AI が見落とした服を足せる。行ごとに「照合／新しく登録／無視」を選べる。日付とメモも直せる。

### 9.3 確定直後の演出

- 「確定」を押すと、確認画面が小さなつながりのマップに変わり、今回の服どうしの線が1〜2秒で伸びる。初めての組み合わせは光り、「初めての組み合わせ」と出る。
- タップで閉じるか、そのままマップで遊べる。鏡の前の PC では全画面で見せる。
- `prefers-reduced-motion` のときは、動きを控えめにする。

### 9.4 Looks タブ

1ページに、上から次の順で並べる。

1. 確認待ちのお知らせ
2. つながりのマップの入口カード（開くと、最近よく着ている服が真ん中に来る）
3. よく着る組み合わせ（最近3か月）
4. 月ごとの着画。見出しの右で「写真｜カレンダー」を切り替え、最後に選んだ表示を端末ごとに覚えておく
5. 「去年の○と比べる」（季節の比較）

カレンダー表示の印：

- 確認待ち：橙の点
- 「今日着た」からの提案あり：緑の点
- 記録なし：点線の枠。タップすると、その日付で記録が始まる

写真なしのコーデは、服の写真を並べたタイルで表示する。

### 9.5 季節の比較

- 今の季節の今日までと、去年の同じ月の範囲を比べる。
- 次のカードを出す。
  - 増えた
  - 減った
  - 今年の新顔
  - 去年の定番で今年はまだ。「撮ってみる」から記録を始められる
- そのほか、カテゴリーの割合と、去年の同じ季節の着画を出す。
- 下に「つながりのマップで比べる ›」を置き、マップを去年の同じ時期の期間で開く。

### 9.6 服の詳細ページ：つながりのマップ

今の詳細ページ（写真 → 名前 → AI 診断 → 今日着た）の下に入れる。

- **形**：真ん中にこの服、周りに一緒に着た服を置く。回数が多いほど大きく、近く、線が太くなる。カテゴリーごとに方向を分ける。最近一緒に着た線は濃くする。
- **仕掛け（すべて入れる）**
  1. **動かせる**：ドラッグすると線が伸び、離すとばねで戻る。ふだんはふわっと漂う。真ん中の服を動かすと全体がついてくる。
  2. **タップで真ん中が入れ替わる＋来た道**：画面を移らずにたどれる。上のチップで戻れる。
  3. **ピンチで3段階**：カテゴリー（泡にまとまる）→ 服（上位12着を大きく、残りは小さな点）→ 広がり（上位10着それぞれの相手の相手を最大2着、外側に出す）。ホイール、トラックパッドのピンチ、＋−ボタンでも操作できる。文字は、拡大・縮小しても同じ大きさに保つ。
  4. **たどり方の切り替え**：組み合わせ／入れ替え（同じ役割の服）。
  5. **期間のスライダーと再生**：最近3か月／去年の同じ時期／全部。3か月の枠を動かし、▶ で時間を進めて再生する。
  6. **長押しで2着の詳細**：一緒に着た回数、最後の日、その2着のコーデの着画。
- **出番待ちの服**：外側に最大5着、薄く浮かべる。真ん中の服と同じカテゴリーは出さず、長く着ていない服を優先する。タップすると「〇〇 × △△、合わせて撮ってみる？」と出て、2着を選んだ状態で記録が始まる。
- **自分で付けた関係**：点線で表示する。
- **「マップ｜一覧」の切り替え**：画面の読み上げを使う人や、正確な回数を見たいときのために付ける。一覧はカテゴリーごとに回数の多い順に並べる。
- 見本：`.superpowers/brainstorm/30486-1792831906/content/relation-map-demo.html`（このデモの動きを本実装の基準にする）。

### 9.7 小さな画面

- **写真なしで記録**：Closet の服をカテゴリーのタブで選び、選んだ服を下にチップで並べる。日付の初期値は今日。1着選ぶと「よく合わせる服」を上に出す。
- **自分で付ける関係**：服の詳細ページの「関係」から「＋追加」を押し、同じ選択画面で服を選ぶ。
- **「今日着た」からの提案**：「今日着た」を押したのにコーデになっていない服があれば、Today のカードに「今日着た3着をコーデにしますか？」と出す。押すと、選択画面が選んだ状態で開く。提案から自動でコーデを作ることはしない。

## 10. エラーの扱い

| 場面 | 扱い |
|---|---|
| カメラの許可がない、カメラがない | 理由を出し、アップロードに切り替える |
| 録画に対応していない | 写真だけ撮る |
| アップロードの失敗、通信が切れる | メディアごとに「もう一度送る」。同じ依頼 ID なので二重にならない |
| Stream の変換の失敗 | メディアを `failed` にし、送り直しか削除を選べる。コーデの記録はできる |
| AI の解析の失敗、時間切れ | `analysis_status = failed`。「もう一度解析」か「手で選ぶ」 |
| 見比べの失敗 | ルールの順位だけで続ける |
| 他人のデータへの参照 | RPC がエラーを返す。画面には一般的な失敗の言葉だけを出す |
| Cloudflare の削除の失敗 | 削除待ちのキューに残し、あとでもう一度試す。DB の削除は成功として扱う |
| 署名付き URL の期限切れ | 画面を開き直すと作り直す |

## 11. テスト

### 11.1 計算の部分（`node --test`、TDD で先にテストを書く）

- 候補の順位付け：点数と理由。
- 月ごとのサマリー作り：着用記録の件数、着た日数（同じ日の重複は1日）、コーデに入った回数。確認待ちのコーデは入れない。
- 期間の足し算：季節、年をまたぐ冬、去年の同じ時期。
- 関係の計算：入れ替え候補、相手の相手、カテゴリーごとのまとめ、出番待ちの選び方、初めての組み合わせの判定。
- 季節の比較のハイライト。
- マップの段階ごとの配置（角度と距離）。動き（ばね）は、ここではテストしない。
- EXIF から日本時間のコーデの日付を出す処理、「今日着た」からの提案のまとめ方、カレンダーの印。
- Cloudflare の署名付き URL・トークンの作成（鍵と時刻を固定）と、webhook の署名の確認。

### 11.2 DB（Docker の Postgres、`supabase/tests/run-0XX.sh`）

- RLS：他人のコーデ・メディア・服・関係・サマリーを、読むことも書くこともできない。
- `confirm_outfit`：参照するものがすべて本人のものか確かめる。同じ依頼 ID で二重にならない。着用記録が付く。過去の日付で確定しても `last_worn_at` が古くならない。日付を別の月に直したら、両方の月のサマリーが作り直される。
- アーカイブと完全な削除で、履歴と集計が正しく残る、または消える。
- 全期間の作り直しの結果が、少しずつ更新した結果と一致する。
- `record_wear_today` が、今までと同じ回数・最終着用日になる。

### 11.3 差し替え部品

- 「見分ける」「見比べる」「MediaStore」はダミーで試す。ダミーの認識結果から、候補の順位と判断の記録が保存されるか。Cloudflare の削除に失敗したときに、削除待ちが残るか。
- 本物の Gemini と Cloudflare は、`scripts/test-image-analysis.mts` のような手動スクリプトで確かめる。サンプルの着画で、1位の候補の正解率を測る。

### 11.4 画面（手動の確認リスト）

- カメラ：左右反転、カウントダウン、カメラの選択、録画できないときに写真だけになるか。
- iPhone の Safari からのアップロードと、撮影日の読み取り。
- 実機でのピンチ、ドラッグ、長押し。
- `prefers-reduced-motion`。
- Stream の通知が届かない環境で、状態の確認に切り替わるか。
